# «Смотритель» — интерактивный сериал

Вертикальный анимационный сериал (1080×1920, 30 к/с), где сюжет выбирают комментарии. Всё — сценарий, графика, анимация, озвучка, музыка и шумы — собирается из кода одной командой.

| Что | Где |
|---|---|
| Готовая серия 1 | [`out/ep01.mp4`](out/ep01.mp4) |
| Библия сериала: мир, персонажи, тайна, сезон, интерактив | [`docs/BIBLE.md`](docs/BIBLE.md) |
| Сценарий серии 1 с таймкодами | [`docs/EP01_SCRIPT.md`](docs/EP01_SCRIPT.md) |

## Как это устроено

```
episodes/ep01/lines.json   текст диктора и реплик (кто, что, паузы)
episodes/ep01/episode.js   раскадровка: сцены, персонажи, плашки, камера
episodes/ep01/voice/       синтезированные реплики (кэш)
engine/                    движок анимации, персонажи, декорации, шрифты
tools/tts.py               озвучка → длительности реплик → таймлайн серии
tools/render.js            покадровый рендер через headless Chromium
tools/audio.py             музыка, шумы, сведение с голосом
tools/build.sh             всё вместе → out/epNN.mp4
tools/tg_send.py           отправка серии владельцу в Telegram
```

Главный принцип: **таймлайн задаёт озвучка**. Сначала синтезируются реплики, по их длине строится `timing.json`, а анимация привязывается к репликам и даже к отдельным словам: `c.Wd('h2', 'долг')` — момент, когда диктор произносит «долг». Поменял текст — всё остальное подстроится само.

Звуки тоже привязаны к картинке: каждая плашка, карточка и событие регистрируют свой звук, а рендер выгружает их в `cues.json` для сведения.

## Сборка

Нужны: Node.js с Playwright (Chromium), Python 3.10+, ffmpeg.

```bash
pip install -r requirements.txt
tools/build.sh ep01          # озвучка → кадры → звук → out/ep01.mp4
```

По шагам:

```bash
python tools/tts.py episodes/ep01              # озвучка + build/ep01/timing.json
node tools/render.js ep01 --stills 12.5,40,150 # быстрые кадры-превью
node tools/render.js ep01                      # все кадры
node tools/render.js ep01 --range 76-105       # перерисовать только кусок
python tools/audio.py episodes/ep01            # build/ep01/mix.wav
```

Предпросмотр в браузере: поднять любой статический сервер в корне проекта и открыть `engine/stage.html?ep=ep01&play=1` (или `&t=42.5` для конкретной секунды).

## Озвучка

Реплики синтезируются нейроголосами через `edge-tts` (нужен доступ к `speech.platform.bing.com`). Голоса, темп и высота задаются в `lines.json` → `voices`.

**Интонация.** У каждой реплики в `lines.json` есть `parts` — куски фразы со своей подачей: `[текст, темп %, высота Гц, пауза после]`. Поправки прибавляются к базовым настройкам голоса: напряжённые фразы идут ниже и медленнее, тревожные — быстрее, перед ключевыми словами ставится пауза. Чтобы поменять подачу, правь числа и пересобирай — анимация подстроится под новую длину.

**Длина.** `max_duration` в `lines.json` — потолок длины серии в секундах (178 — запас под лимит YouTube Shorts в 180 секунд); если серия длиннее, `tts.py` об этом предупредит. `pause_scale` сжимает паузы внутри фраз.

**Сменить голос** — поменять `voice` в `voices` (список голосов: `edge-tts --list-voices`). Готовые реплики кэшируются в `episodes/ep01/voice/`, так что пересборка без изменений текста сети не требует.

**Заменить синтез живым голосом:** запиши реплику и положи её в `episodes/ep01/voice_override/<id>.wav` (например, `h1.wav`). Сборка возьмёт запись вместо синтеза и сама подгонит под неё анимацию.

Перед публикацией с монетизацией проверь условия использования выбранного голоса или переозвучь серию своим.

## Отправка в Telegram

`tools/tg_send.py` отправляет готовую серию через твоего бота — **только тебе**, в один привязанный личный чат по числовому ID. Бот при этом никому не отвечает и входящие сообщения не читает.

```bash
export TG_BOT_TOKEN=...                    # токен от @BotFather; в репозиторий не попадает
python tools/tg_send.py --bind маяк        # один раз: напиши боту в личку «маяк» — ID запомнится в .tg.json
python tools/tg_send.py out/ep01.mp4       # файл как есть, без пережатия (до 50 МБ)
python tools/tg_send.py out/ep01.mp4 --video   # как видео, играет прямо в чате
python tools/tg_send.py --check            # проверить настройки
```

Вместо `--bind` можно задать ID переменной `TG_CHAT_ID`. Если токен и ID заданы, `tools/build.sh` сам отправляет серию в Telegram сразу после сборки. В группы и каналы скрипт не шлёт: перед отправкой он проверяет, что привязанный чат — личный.

## Как сделать следующую серию

1. Скопировать `episodes/ep01` в `episodes/ep02`, очистить `voice/`.
2. Переписать `lines.json`: сцены и реплики. Начало серии — результат голосования и карточки «из комментариев» (ветки серии 2 расписаны в библии).
3. В `episode.js` собрать сцены из готовых деталей:
   - декорации: `A.set.lighthouse(id, 'day' | 'eve' | 'night')`, `A.set.cabin`, `A.set.room`, `A.set.road`, `A.set.bokeh`;
   - персонажи: `A.person('hero' | 'lyadov' | 'nyura' | 'notary' | 'ded')` — умеют ходить, говорить, менять лицо, поднимать руки;
   - интерфейс: `c.label` (плашка), `c.bubble` (реплика), `c.card` (карточка), `c.ring` (кольцо-акцент), `c.counter` (бегущее число);
   - звук: `c.sfx`, `c.music`, `c.amb`.
4. `tools/build.sh ep02`.

Новый персонаж — это запись в `KINDS` в `engine/art.js` (цвета одежды, причёска). Новая декорация — функция в `engine/sets.js`.
